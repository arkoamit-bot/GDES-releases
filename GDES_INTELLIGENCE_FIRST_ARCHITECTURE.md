# Philosophy

## Stop Building More Modules.

## Start Building Better Intelligence.

After reviewing the current GDES architecture, the project has reached a stage where adding more Django apps and modules produces diminishing returns.

Future development should focus on making the existing system significantly more intelligent rather than significantly larger.

The goal is not to build the biggest nephrology software.

The goal is to build the smartest nephrology assistant.

---

# New Development Principle

Every new feature must answer one question:

> **Does this make the clinical recommendation more intelligent?**

If the answer is **No**, the feature should not be implemented.

# OpenCode Implementation Instructions

This document supersedes any previous proposal that emphasized creating numerous new modules.

Implementation priorities are:

1. Refactor existing code before creating new apps.
2. Reuse existing models and services wherever possible.
3. Build a single **Clinical Intelligence Service** that orchestrates the current Knowledge Engine, Recommendation Engine, Governance Layer, and external evidence providers.
4. Integrate free public evidence APIs:
   - PubMed
   - Europe PMC
   - OpenAlex
   - CrossRef
5. Integrate GPT-5 API as an independent clinical reviewer and explanation engine.
6. Design Vera support as an optional clinician-invoked consultation workflow with automatic prompt generation, not as a mandatory dependency.
7. Prioritize reasoning quality, explainability, and workflow efficiency over architectural expansion.
8. Maintain backward compatibility with all existing GDES functionality.
9. Optimize for maintainability, extensibility, and long-term clinical reliability.
